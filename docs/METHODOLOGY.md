# 题库研究与排序方法

## 目标和边界

题库服务的目标岗位是 Java 后端与 AI / Agent 应用开发的实习、校招和 0–1 年经验职位。它回答“在当前收录的公开证据下，初学者应先练什么”，不声称统计了全互联网，也不把公开帖子数量解释为真实录取概率。

快照日期：2026-08-28。重新调研时应更新 `research/sources.json` 的快照日期和每个来源的发布日期。

## 来源分层

从高到低使用以下证据：

1. 近期真实面经：明确公司、轮次或岗位，正文包含直接问题；这是排序的主要信号。
2. 近期多公司复盘：用于发现跨公司共性；含推广、疑似加工答案或公司标注冲突时降权并写入备注。
3. 公开岗位要求：验证招聘方明确要求的语言、框架和工程能力，不作为某道原题出现的证明。
4. 持续维护的面试指南：交叉验证稳定基础并补齐知识结构，不能压过最新面经。
5. 官方文档和研究：校验接口与技术事实，不用于制造“高频”印象。

转载内容尽量回溯原帖。同一经历的多次转载只登记一次，不能通过转载数量抬高权重。

## 去重与拆题

先把近义问法归并为“概念”，例如“HashMap 为什么线程不安全”和“并发写 HashMap 有什么问题”归到 HashMap。再对每个概念生成五种独立训练角度：

- 定义：是什么、解决什么问题。
- 机制：内部过程和因果链。
- 应用：项目中如何设计和验证。
- 故障：错误现象、原因和排查。
- 对比：与相邻方案如何选型。

内置目录以 100 个后端概念和 40 个 Agent 概念为稳定基线；经用户审阅应用的动态概念继续按每个 5 个角度扩展。当前为 145 个后端概念和 52 个 Agent 概念，共 985 个可独立作答的问题，不是用同义改写虚增数量。动态概念保持追加式顺序，不能插入内置目录或重排旧条目，以保护既有题目 ID 和浏览器学习进度。

Java 后端采用主流八股站点常见的同级专题：Java 基础、Java 集合、Java 并发、JVM、Spring 生态、MySQL、Redis、计算机网络、操作系统与 Linux、消息队列、分布式与微服务、系统设计与场景。每个专题再维护二级知识组和具体知识点；五类问法是跨专题筛选维度，不作为知识目录父级。分类迁移只改变元数据，不改变概念顺序和稳定题目 ID。2026-08-28 的覆盖审计及具体 URL 见 [COVERAGE_AUDIT.md](COVERAGE_AUDIT.md)。

增量更新时，内置概念和此前由更新管线加入的动态概念会一起进入同义归并；相同 URL 复用既有来源记录，新发现的支持关系补到来源与概念上，不用重复来源或重复概念制造频次。一次只能运行一个分析任务，取消会中断后续抓取与模型请求，并且不会留下可应用草案。

## 重要度计算

每个概念先由研究者给出 1–5 的岗位优先级。每道题的分数计算为：

```text
importance = min(98,
  38
  + 概念优先级 × 7
  + 考查角度奖励（2–5）
  + 多来源加权支持（最多 13）
  + 来源多样性（最多 4）
)
```

“多来源加权支持”逐项累计，来源类型系数为：面经 1.0、岗位 0.6、维护指南 0.35、研究 0.3、官方资料 0.25。2026 年前的来源再乘 0.55，非直接问题证据乘 0.8。累计值乘 4 后取整，最高 13。

来源多样性按题目关联来源中的不同公司或来源主体计算，最高 4。公式实现位于 `scripts/generate-questions.mjs`，生成结果同时保存 `weightedSupport`，因此可以复算。

等级只是方便筛选：

- `core`：重要度 ≥ 88
- `high`：重要度 ≥ 74
- `extended`：其余

## 考察口径与学习位置标注（更新题库时）

- 高频排序以近期真实面经为主；同时要求 AI 结合 JavaGuide、面试鸭、小林coding 等八股网站交叉验证概念表述与覆盖面。
- AI 为每个知识点输出 `learningHints`：站点、对应章节名、直达链接（不确定的链接留空）。学习位置仅作学习辅助，不参与 importance 计算。
- 八股网站内容本身不作为「高频证据」登记来源，避免把教材覆盖率虚增为面试出现频率；两者在界面中分开展示（「高频证据」与「八股文网站对应章节」）。

## AI 评分复核（更新题库时）

本地公式是基线，不是最终裁决。更新题库时，受影响的题目（新题 + 分数变化的旧题，最多 40 道，按重要度取前）会交给 AI 复核：

- **约束 skill**：公式规则、来源类型系数、层级阈值作为系统提示词的硬性约束。
- **边界**：最终分必须是 0–98 的整数，与基线差 ≤6；越界调整会被本地系统驳回并回退公式分。
- **理由**：每次调整必须给出理由（≤120 字），写入 `scoreNote`，并在更新报告展示「基线 → AI 最终」。
- **持久化**：调整记录保存在 `research/ai-scores.json`，重新生成题库时自动应用；若公式基线变化（来源增减），旧调整自动失效。
- **失败回退**：AI 复核调用失败时保留公式基线分，并在进度中标注。

每个分数要么来自可复算的公式，要么来自带理由、有边界的 AI 判断，二者都可在更新报告与题目数据中追溯。

## 证据标签

- `strong`：至少有三个 2026 年直接面经来源、加权支持 ≥ 2，且概念优先级 ≥ 4。
- `medium`：有面经或岗位来源，但不满足 strong。
- `foundation`：主要由基础指南或官方资料支持，或属于默认前置知识。

`recentInterviewSamples` 表示当前登记并关联到该概念的近期面经样本数量，不代表全网频次。用户界面应始终同时展示这一限制。

## 公司专项与样本趋势

- 只把“有 http/https 原文链接、有可核验发布日期、正文包含直接问题证据”的面经纳入趋势；手动粘贴且无链接/日期的材料可以辅助答案，但不提升近期频次。
- 先按 `concept` 去重，同一概念的定义、机制、应用、故障和对比五个角度只计一次；同一来源对一个概念也只计一次。
- 近期窗口为快照日前 90 天，对照窗口为此前 90 天。趋势同时展示累计样本、独立明确公司数、最近观察日期、信号标签和置信度。
- 公司专项只使用能明确归属单一公司的直接面经；“多公司”“汇总”或公司标注冲突的来源不进入任何单一公司题单。
- 互动关注度仅接受页面正文明确出现的浏览、点赞、收藏、评论非负整数；缺失时显示未知，AI 不得补猜。
- 八股、官方文档、研究资料不进入近期趋势。页面必须同时展示平台分布、日期范围、排除样本和限制，统一称为“可审计的已采集样本趋势”。

实现位于 `scripts/source-insights.mjs`，公开接口为 `GET /api/insights`。

## 高频证据与学习来源分离

`evidence.sourceIds` 只解释题目为什么进入题库和如何排序；`learningSourceIds` 用于给初学者继续学习。Oracle、OpenJDK、Spring、MySQL、Redis、Kafka、Netty、NGINX、Docker、Elastic、MCP、LangGraph 与 OWASP 等官方资料不会因为“权威”就被当作真实面试出现次数，也不会虚增高频标签。

## 质量控制

`npm run validate` 会阻止以下内容进入正式题库：

- 总数或两条路线数量错误；
- ID 或标题重复；
- 关键字段为空；
- 精简答案过短；
- 缺少至少两个评分点；
- 引用了不存在的来源。

`npm run test:coverage` 另行固定 12 个 Java 后端专题中的 123 个主流目录必备检查项，要求每项存在、分类正确并拥有五类问法；同时断言指南、官方与研究资料不能取得面经趋势资格。完整发布验证 `npm run verify` 会同时执行生成、数据校验和覆盖回归。

“已人工复核”是显式状态，不由概念优先级自动推断。复核记录位于 `research/content-reviews.json`，按稳定题目 ID 保存日期、说明和核查来源；生成器只对有效登记输出 `contentStatus: reviewed`，校验器会阻止不存在的题目、非法状态、缺失来源、批次数量不一致或生成状态不一致。当前前两批覆盖最高排名的 40 个核心概念，其定义和机制共 80 题。

自动检查不能替代事实复核。新增内容时，优先逐题复核 core 题，再处理 high 和 extended；变化快的模型接口、框架和协议还应复查对应官方文档。

## 已知偏差

- 公开面经由用户主动发布，岗位、地区、候选人背景和失败经历分布不均。
- 有的帖子包含二次整理或推广，来源权重已降低，但无法完全消除噪声。
- 一条帖子可能列出多个问题，当前版本记录“概念得到该来源支持”，没有抓取并保存网页全文或伪造精确词频。
- 公司面试会随团队和面试官变化；时间越久，排序价值越低。
- Agent 岗位仍快速变化，项目深挖、评测和工程可靠性通常比死背单一框架 API 更稳定。
